Lead Management Automation

An event-driven n8n process that validates incoming leads, checks HubSpot for duplicates, creates or updates contacts, sends a confirmation, and returns structured JSON.

01 / CONTEXT

The challenge
to solve.

Inbound leads arrive from websites, landing pages, and other forms. Manual processing creates delays and data-quality risks: third-party form submissions were handled manually, CRM records were entered by hand, follow-ups were inconsistent, and duplicate contacts accumulated in HubSpot.

02 / AUTOMATION LOGIC

How the flow
works.

The steps are sequenced to move information forward deliberately.

  1. 01

    Receive lead data

    An n8n webhook accepts incoming lead information in real time from an external source.

  2. 02

    Validate required fields

    The workflow checks required data before any CRM write. Incomplete submissions fail fast with a clear error message.

  3. 03

    Search for an existing contact

    A HubSpot Contacts Search API request checks for a contact by email before any record is written.

  4. 04

    Create or update

    An If node branches on the search result. Existing contacts are updated; new contacts are created.

  5. 05

    Send confirmation

    An automated confirmation email is sent to the lead.

  6. 06

    Return the result

    The workflow sends a structured JSON API response to the calling application, indicating what happened.

03 / BUILD NOTES

Details that
matter in production.

01

Scoped authentication

HubSpot Private App Access Token authentication is used instead of a legacy API key. Write access is scoped to contacts.

02

Deduplication first

The workflow checks for a contact before creation and branches on actual API response data.

03

System integration

Structured JSON responses support communication between the workflow and its calling application.

FIELD NOTE

Debugging note

During development, the HubSpot Search API rejected requests even though authentication was configured correctly. The cause was a malformed request body. This highlighted the importance of checking API documentation and debugging requests systematically.

04 / OUTCOME

What changed
in the process.

  • ✓Removes manual CRM entry from the intake process and checks for existing contacts before creating records.
  • ✓Returns a structured response for each lead to the calling application.
  • ✓Provides a reusable pattern for businesses receiving leads from websites, landing pages, or third-party applications.

HANDOFF-READY NOTES

Designed to be
maintained.

01

API endpoint reference

Records the HubSpot Contacts Search endpoint’s method, URL, authentication type, request body structure, and the total response field used for branching.

02

Conditional logic

Documents the rule: if total > 0, update the contact by ID; otherwise, create a contact. It also identifies edge cases such as exact copies, malformed email addresses, and API errors.

03

Maintainer note

Records the Search API request-body details to support troubleshooting.
