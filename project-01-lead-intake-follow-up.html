01 / CONTEXT

The challenge
to solve.

Fast lead response matters, but a single automated blast can feel impersonal, and a generic second marketing email may not prompt a reply. Manual CRM entry also creates delays and duplicate records. The goal was to engage leads immediately, then follow up in a way that feels more like a human check-in.

02 / AUTOMATION LOGIC

How the flow
works.

The steps are sequenced to move information forward deliberately.

  1. 01

    Receive lead data

    An n8n webhook accepts submissions in real time from external sources such as Webflow, Elementor, or custom HTML forms. It is configured for POST, with GET available for straightforward forms. This event-driven approach avoids polling a spreadsheet every ten minutes.

  2. 02

    Create or update the CRM contact

    The HubSpot node uses Create or Update, mapping fields such as email and firstname from incoming JSON. Its existing-contact check helps prevent duplicates and keep CRM records clean.

  3. 03

    Send an immediate confirmation

    On the successful HubSpot path, Gmail/SMTP sends a promptly triggered, professionally formatted HTML email.

  4. 04

    Wait before following up

    A Wait node pauses this lead's execution for a configured interval, such as 24 hours, without stopping other workflow executions.

  5. 05

    Continue the email thread

    A second Gmail node uses Thread ID logic to send the follow-up as a reply to the first email, making it a personal check-in rather than a separate marketing blast.

03 / BUILD NOTES

Details that
matter in production.

01

Event-driven intake

Webhook-based, real-time intake rather than scheduled spreadsheet polling.

02

Clean CRM data

Dynamic field mapping and HubSpot create-or-update checks support data flow and deduplication.

03

Human-paced follow-up

A configurable wait and Thread ID logic keep the follow-up in the original email conversation.

04

Scoped access

HubSpot authentication uses a Private App access token rather than a legacy API key. Write access is scoped only to contacts.

HANDOFF-READY NOTES

Designed to be
maintained.

01

Intake specification

For the developer connecting the form, it documents the required fields (firstname, lastname, and email), optional fields, and validation behavior. A missing field produces “Missing field: <field>” and halts the workflow before any CRM write.

02

Follow-up timing guide

An SOP for sequence maintainers explains the timing and Thread ID constraint: the second email must appear as a reply. Maintainers changing email providers should account for this before editing the workflow.

03

Credential and scope record

Documents the contacts-write-only HubSpot Private App token, why that scope was chosen, and where the credential is stored so it can be rotated without over-provisioning access.
