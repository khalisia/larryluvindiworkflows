Lead Scoring & Deal Creation Automation

An n8n workflow that validates and scores incoming leads, deduplicates HubSpot contacts, opens a deal, notifies both customer and sales, and returns the computed result.

01 / CONTEXT

The challenge
to solve.

Inbound leads can vary significantly in company size and buying intent. Treating every inquiry the same can divert sales attention, while manual CRM entry risks duplicate contacts and inconsistent deal creation. The form also needs a clear response confirming what happened. The workflow was designed to determine whether a lead is valid, how it scores, whether its contact is new or returning, and what happens next.

02 / AUTOMATION LOGIC

How the flow
works.

The steps are sequenced to move information forward deliberately.

  1. 01

    Receive the lead

    A POST request to /new-lead starts the workflow. A dedicated response node holds the connection open and returns the computed result at the end, rather than sending an immediate acknowledgment.

  2. 02

    Validate required fields

    A JavaScript node checks for firstname, lastname, and email. If any is missing, it throws “Missing field: <field>”; incomplete submissions do not reach a CRM write.

  3. 03

    Calculate a rule-based score

    The workflow awards 40 points when employee count is greater than 100 and 30 points when the message includes “pricing.” It merges the result into the original data as leadScore. The documented test fixture—a 120-employee company asking about pricing—scores 70.

  4. 04

    Find or create the contact

    The workflow searches HubSpot’s Contacts Search API by email before writing. If total is greater than zero, the existing contact is updated by ID; otherwise, a contact is created with name, email, and company.

  5. 05

    Create a deal

    Each handled lead gets a HubSpot deal named after the lead in the default pipeline.

  6. 06

    Notify and respond

    Gmail sends the lead a personalized HTML confirmation and sends the internal sales team a plain-text alert containing the lead’s name and email. The final webhook response is JSON, for example: {success:true, leadScore:70, status:processed}.

03 / BUILD NOTES

Details that
matter in production.

01

Computed response

The response-node pattern returns workflow-computed data, including the lead score, to the calling application.

02

Data integrity

Validation happens before CRM writes, and contact deduplication happens before contact creation.

03

One reusable score

The score is calculated once and carried through to both emails and the API response. Its deterministic rules can be extended with additional signals.

04

Scoped authentication

HubSpot authentication uses a Private App access token with write access scoped to contacts.

04 / OUTCOME

What changed
in the process.

  • ✓A single webhook submission triggers validation, scoring, contact deduplication and create-or-update handling, deal creation, two email notifications, and a structured response to the source application.
  • ✓Reduces manual CRM entry and helps avoid duplicate contacts; sales receives the lead score with the notification.

HANDOFF-READY NOTES

Designed to be
maintained.

01

Webhook API contract

Documents /new-lead, including method, path, required and optional fields, authentication, response schema, and response-node behavior.

02

Scoring specification

Records the scoring rules and worked test fixture so thresholds can be reviewed consistently.

03

Error reference and limitations

Documents the exact validation message and guarantee that failed validation performs no CRM write. The deal is not yet associated with the contact, and the deal amount is a placeholder.
